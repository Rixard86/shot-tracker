# HANDOVER: ShotPuck (for the next agent)

Read this first, then `README.md`. Everything below is the state as of 2026-09-26.

## 1. What this is

ShotPuck is a Ø40 × 9.95 mm BLE puck that screws (5/16-24 stud) onto the free face of an **Avalon barebow riser weight**. It counts arrow shots with an accelerometer and reports them to the user's own **Flutter/PowerSync archery scoring app**.

- MCU: Raytac MDBT50Q-512K (nRF52833).
- Accelerometer: LIS2DE12.
- Cell: Varta CP1654 (Li-ion coin).
- Charger: MCP73831, via a magnetic pogo connector.

Deliverable status: **v0.1 design package complete and verified off-device. No hardware has been built yet.**

## 3. Hard rules of the codebase (do not break)

1. **`layout.json` is the only source of geometry.**
   - Readers: `mechanical/puck.py` (enclosure and balance) and `hardware/gen_pcb.py` (placement, holes, keep-outs).
   - Change geometry there, then re-run both.
2. **`hardware/design.py` is the only source of the circuit.**
   - `.kicad_sch` and `.kicad_pcb` are **generated**; never hand-edit them in the repo.
   - Flow: edit `design.py` → `gen_sch.py` → `check_netlist.py` → `gen_pcb.py` → `gen_bom.py` → re-export fab files.
3. **`firmware/src/shot_detect.c` is shared by the firmware and the simulation.**
   - Any detector change must be re-run through `firmware/sim/simulate.py --stress` and still print `RESULT: PASS` before shipping.
4. **Wire protocol lives in `firmware/src/protocol.h`** and is documented in `docs/PROTOCOL.md`.
   - Keep the two in sync.
   - Bump `PROTO_VERSION` on any layout change, because the Flutter app parses these bytes.
5. `mechanical/out/trim.json` is generated by `puck.py` and consumed by `gen_pcb.py` (trim-pin keep-out). Run `puck.py` before `gen_pcb.py`.

## 6. Key design facts (easy to get wrong)

- **Power:** cell → U1 **VDDH** (nRF52833 high-voltage mode). REG0 drives **VDD = 3.0 V**; firmware writes UICR REGOUT0 on first boot and resets once. VDD powers the LIS2DE12, LED and SWD VCC.
- **Battery voltage:** read via SAADC `NRF_SAADC_VDDHDIV5`. The define needs `#include <zephyr/dt-bindings/adc/nrf-saadc-v3.h>`.
- **Charge inhibit logic:**
  - PROG → R1 20k → Q1A. Q1A's gate is pulled to VIN by R2 (1M).
  - Q1B (gate = CHG_INH on P0.27, R3 100k pull-down) pulls Q1A's gate low, which floats PROG and disables charging.
  - **Default = charging allowed** (deliberate, so a flat cell can recover).
- **Charge status:** STAT → D2 BAT54J → P1.09. The GPIO pull-up is enabled **only while VBUS is detected**, which avoids standby leakage.
- **Pins:**

  | Signal | nRF pin | MDBT50Q pad |
  |---|---|---|
  | I2C SCL | P0.04 | 20 |
  | I2C SDA | P0.06 | 22 |
  | ACCEL_INT1 | P0.08 | 24 |
  | CHG_STAT | P1.09 | 26 |
  | CHG_INH | P0.27 | 16 |
  | LED | P0.13 | 37 |
  | SWD | SWDIO / SWDCLK | 51 / 53 |
  | VBUS (charger present, System-OFF wake) | VBUS | 32 |

  - LIS2DE12 is at I2C address 0x18.
  - Avoid P0.00/P0.01 (LFXO) and P0.19 (duplicated in the KiCad symbol).
- **Clocks and regulators:** 32 kHz from RC; REG0/REG1 in LDO mode. The MDBT50Q LFXO and DC/DC inductor are not confirmed, so this is the safe default.
- **Board orientation:**
  - Module rotated 90°, antenna toward −x at the rim; cell centred at (8.5, 0); connector at (0, 12).
  - Screw bosses at r = 17 mm, angles 30/150/270°.
  - CP1654 tabs are radial: + pad at (8.5, −9.4), − pad at (8.5, +9.4), both outside the cell. No top copper under the cell (rule area).
- **Keep-outs in `gen_pcb.py`:**
  - Antenna region to the rim.
  - Top copper under the cell.
  - 3 boss faces, Ø3.8 + 0.3 mm.
  - 0.35 mm rim ring.
  - The low trim pin (footprints not allowed).
- **Ground strategy:** every GND SMD pad gets a stub + via before routing (`gnd_fanout`). Freerouting routes signals only. Then `stitch()` adds grid GND vias and the pours fill with island removal. U1 pad 55 gets no fanout via; it connects through the pour and DRC is clean.
- **BLE:**
  - Advertises only while ACTIVE, plus a 120 s linger.
  - EVENT notification is 24 bytes, so ATT MTU must be ≥ 27; the device requests 65.
  - Every detector candidate (accepted or rejected) is notified, for threshold tuning.
  - No pairing in v1.

### Gotchas already paid for

- **CMake 4.x breaks Zephyr 4.1.** Pin 3.x.
- **KiCad 7 CLI has no `sch erc` or `pcb drc`.**
  - Connectivity is checked with `check_netlist.py`.
  - DRC runs via `pcbnew.WriteDRCReport`.
  - Tell the user to run ERC in KiCad 8/9.
- **Missing library-path env vars** cause "lib_footprint_issues" DRC noise. Set the `KICAD7_*` variables.
- **pcbnew 7 API specifics:**
  - Pads need both `SetPos0` and `SetPosition` in library footprints.
  - Netclass is `ds.m_NetSettings.m_DefaultNetClass`.
  - LSET has no `|` operator: use `AddLayer`.
  - NPTH pads use `p.UnplatedHoleMask()`.
- **Session import:** `pcbnew.ImportSpecctraSES` works only inside the GUI. `gen_pcb.import_ses()` parses SES itself (units 0.1 µm, y up) and dedupes echoed vias and tracks.
- **Freerouting quirks:**
  - It can loop forever on a blocked connection, ignoring `-mp`, so `route()` has a subprocess timeout.
  - It once reported a net "complete" while leaving a pad open. Always trust KiCad DRC, not the router log.
- **Background jobs** (`nohup … &`) are sometimes killed when the tool call returns. Run long jobs in the foreground under `timeout 290`.
  - `gen_pcb.py` overwrites the board before routing, so back it up first.
- **`pkill -f <pattern>` can kill your own shell** if the pattern appears in the command line. Use `pgrep -x java | xargs -r kill -9`.
- **Simulation runtime:** the full sim with `--stress` at 36 sessions takes ~4–5 min. Use `python -u` for live output.

## 9. Known limitations / risks

- **Thresholds are unvalidated on real bows.** The weak-bow sim shows recall collapsing if the real release shock or rotation is smaller than modelled. Tuning from logged EVENT data is the #1 on-device task (`docs/VALIDATION.md` §3).
- **Hard grab off the stand** is the only false-positive source in simulation (slap ≥ 6 g plus lift).
- **Load-bearing but unverified assumptions:** nRF52833 VBUS wake from System OFF; MDBT50Q LFXO / DC-DC inductor presence; BLE range through the PC cap next to the aluminium base.
- **Event log is RAM-only** (128 entries); only `total` and `seq` persist.
- **No watchdog, no OTA/DFU.** MCUboot partitions exist in the DTS but no bootloader is built.
- **Firmware reads the FIFO sample by sample** (25 I2C transactions per watermark). A burst read would cut ACTIVE current; verify the LIS2DE12 address roll-over first.
- **Battery life of 4–6 months at 2 h/day is an estimate.** Measure with JP1 cut.
- **Material constraint:** PC cap + liquid threadlocker = stress cracking. Use nylon-patch screws only.
